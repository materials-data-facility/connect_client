## TOP BUGS

1. Token-only publish can submit local absolute paths instead of uploading files.
   - Refs: `src/mdf_agent/core/backend_client.py:84`, `src/mdf_agent/core/agent.py:733`, `src/mdf_agent/core/agent.py:748`.
   - Why it matters: `MDF_CONNECT_TOKEN` and `--token` are advertised for automation, but they do not populate `_globus_data_token`. Local `data_sources` are left as local filesystem paths in the payload and likely fail backend validation or publish unusable data.

2. Clone zip extraction is vulnerable to path traversal.
   - Refs: `src/mdf_agent/core/agent.py:1273`, `src/mdf_agent/core/agent.py:1277`.
   - Why it matters: A malicious or compromised `download_url` archive can write outside the output directory via `../` or absolute paths.

3. `mdf clone --transfer` only transfers the first Globus source.
   - Refs: `src/mdf_agent/core/agent.py:1378`, `src/mdf_agent/core/agent.py:1398`, `src/mdf_agent/core/agent.py:1403`.
   - Why it matters: Multi-source datasets silently get partial transfer tasks while reporting success.

4. Zip-to-HTTPS fallback after bad zip cannot work for archive-selected plans.
   - Refs: `src/mdf_agent/core/agent.py:1090`, `src/mdf_agent/core/agent.py:1104`, `src/mdf_agent/core/agent.py:1113`, `src/mdf_agent/core/agent.py:1220`.
   - Why it matters: When auto selects zip, `_prepare_clone` does not resolve file list. If the URL is not a valid zip, fallback returns "No HTTPS-downloadable files" instead of doing the advertised file-by-file fallback.

5. Hidden `mdf init` alias is broken by direct Typer command-function call.
   - Refs: `src/mdf_agent/cli/main.py:1629`, `src/mdf_agent/cli/main.py:1640`, `src/mdf_agent/cli/manifest_cmd.py:40`, `src/mdf_agent/cli/manifest_cmd.py:54`.
   - Why it matters: README-adjacent legacy init path can crash because omitted Typer option parameters default to `OptionInfo`, not real `None`.

6. `mdf import --submit --json` is not JSON-serializable.
   - Refs: `src/mdf_agent/core/agent.py:1506`, `src/mdf_agent/core/agent.py:1518`, `src/mdf_agent/cli/main.py:2566`.
   - Why it matters: The result includes a `ManifestConfig` object and `json.dumps` will fail, breaking the scripting mode.

7. Directory upload can collide files from multiple directories and can upload nested symlink targets outside the intended tree.
   - Refs: `src/mdf_agent/core/agent.py:253`, `src/mdf_agent/core/agent.py:254`, `src/mdf_agent/core/agent.py:256`, `src/mdf_agent/core/agent.py:259`, `src/mdf_agent/core/agent.py:157`.
   - Why it matters: The zip archive preserves prefixes for multiple dirs, but individual uploaded files do not. Also, symlink safety is implemented for zip creation but not for the individual upload plan.

8. Public read commands inconsistently force interactive authentication.
   - Refs: `src/mdf_agent/cli/main.py:1251`, `src/mdf_agent/cli/main.py:1444`, `src/mdf_agent/cli/main.py:1549`, `src/mdf_agent/cli/dataset_cmd.py:84`, `src/mdf_agent/core/agent.py:784`.
   - Why it matters: `mdf search` can be public, but `show`, `related`, `dataset open`, `dataset cite`, and SDK read helpers can trigger Globus login for public data.

9. README SSL verification default is the opposite of code.
   - Refs: `README.md:249`, `src/mdf_agent/core/agent.py:96`, `src/mdf_agent/core/agent.py:98`.
   - Why it matters: Users debugging upload TLS will set expectations incorrectly; code defaults to verifying TLS, README says default false.

10. `mdf stream upload` can fail every file and still exit successfully.
    - Refs: `src/mdf_agent/cli/stream.py:190`, `src/mdf_agent/cli/stream.py:258`, `src/mdf_agent/cli/stream.py:282`.
    - Why it matters: CI/lab automation may treat failed uploads as success because errors are printed but no nonzero exit is raised.
